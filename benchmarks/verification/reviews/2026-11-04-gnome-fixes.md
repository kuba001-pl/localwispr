Protocol and contract:
- Existing GetCursorContext remains read-only and releases all request watches on return. Recognition uses that flow; it never holds a future insertion target.
- New GetInsertionContext has no input and returns (status, before, after, is_replacement, context_token), D-Bus signature sssbs. The daemon owner's unique bus identity is required.
- New InjectBound(request_id, context_token, text, chord, restore, restore_delay_ms), input signature ssssbu, returns the existing preservation boolean. It rejects stale, wrong, expired, or owner-mismatched handoffs; Rust never retries adapted text through an unbound method.
- A handoff holds one focus/range binding for at most 2000 ms; it is replaced by a new authorized insertion-context request, invalidated by owner loss/disable or observed window, Shell focus, caret-location, content property or changed surrounding-range signals, and consumed at key submission. Focus/caret away/back cycles that emit these signals remain invalidated. No input-method vfunc is patched.
- Revalidation checks current input-method identity, focus/window/Shell focus, protection, preedit, caret/anchor offsets, total character count, and at most 256 Unicode characters on either side, excluding the selection. It runs on changed-context signals, on InjectBound entry, after backups before installing sources, and immediately before key submission. Surrounding documents exceeding 64 Ki UTF-16 units are rejected; Rust checks the 64 KiB raw reply limit before deserialization and validates Unicode and token bounds. Only bounded outside text and range metadata are retained in the lease; selected text is not retained or compared.
- Every installed clipboard/PRIMARY source is tracked independently of restoration eligibility. Pre-key cancellation/failure restores known backups or clears still-owned injected sources when no backup exists, including restore=false and failed backup cases. A newer owner is preserved independently for each selection.
- After key submission, cancellation, owner loss and disable do not shorten the normal max(100 ms, configured delay) consumption grace. Disable disposes the keyboard immediately while retaining a bounded selection-owner watch/timer for conditional restoration. A successful restore=false operation intentionally retains dictated text. Backup failures still report preservation=false.
- GNOME insertion on an old loaded extension gets conservative formatting with no context; status is unbound-extension. It never falls through to an unbound AT-SPI snapshot for GNOME adaptation. Other fixed statuses cover unavailable, changed, timeout, denied, protected/terminal fields and invalid handoffs. Recognition provider fallbacks remain unchanged.

This is not an atomic context-plus-paste transaction. GNOME getters/signals can replay committed cache rather than acknowledge a fresh application round trip. Unobservable changes, selected-content-only changes with identical range/outside text, and application changes after the final check cannot be detected. The extension deliberately does not compare selected text. Queued key events cannot be recalled. The grace period is a bounded consumption opportunity, not an application transfer-completion acknowledgement; an application can request data after the grace window. Rust remote cancellation remains request-scoped best effort when its Drop guard sends CancelInject asynchronously. Old loaded extensions lack new handoff/cancellation capabilities until Shell is reloaded through the appropriate session workflow.
