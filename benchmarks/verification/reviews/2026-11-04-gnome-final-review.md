## Limits of approval

There is no atomic application context-plus-paste transaction. GNOME surrounding-text requests can replay cached committed state. Changes that produce neither an observable signal nor a changed final identity/range/outside snapshot remain undetectable; selected-content-only changes with identical range/outside metadata intentionally remain invisible. Application state can change after the final check, and submitted key events cannot be recalled.

The grace interval provides an opportunity for consumption, not an application transfer-completion acknowledgement. Actual applications may request data after the configured grace, and the mocks do not prove real application consumption or PRIMARY-selection behavior. No live Shell reload/enable/disable, real document replacement, native-model inference or microphone acceptance was performed. Old loaded extensions still require the appropriate Shell reload/session workflow to gain the new protocol; their legacy remote cancellation remains unavailable. Rust Drop-triggered `CancelInject` remains asynchronous best effort rather than a confirmed Shell cancellation barrier.

These are explicit limits of the reviewed contract, not newly reproduced blockers. Approval applies to this recorded source snapshot and the requested scope.
